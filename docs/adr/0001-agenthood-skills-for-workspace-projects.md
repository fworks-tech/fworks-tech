# ADR-0001: Agenthood Skills as the Standard for Workspace Projects

**Date:** 2026-08-19
**Status:** Accepted

## Context

The fworks-tech profile and its sibling workspace repos (agenthood, agenthood-site, flabs.tech, atmydesk) share the same operating problem: small, lightly staffed projects where code quality, commit hygiene, and PR standards are enforced by convention rather than machinery. Multiple AI providers and multiple agent runtimes (Claude Code, Codex, opencode, Copilot) operate in the same repos, each with its own prompt format and no shared source of truth.

The Society (19 members — the-scribe, the-architect, the-builder, the-reviewer, the-tester, the-debugger, the-auditor, the-herald, the-librarian, the-doorman, the-oracle, the-envoy, the-sentinel, the-warden, the-steward, the-operator, the-strategist, the-mailman, the-inspector) formalizes each role as a `SKILL.md` file. Those files live once at `~/.agents/skills/<member>/SKILL.md` and are consumed both by local tooling and by the independent TypeScript runtime.

Adoption already happened in practice: fworks-tech's README Recent Activity is LLM-generated by the update workflow, its PR/commit conventions follow the Society, and an Agenthood reviewer workflow install for CI is underway. This ADR records why that standard is right and the lessons learned while integrating it.

## Decision

Adopt Agenthood as the standard skill + runtime + CI-review layer for fworks-tech and repos like it, with `SKILL.md` as the single source of truth.

1. **Member skills** — each role's prompt lives in `SKILL.md` (front-matter + prose). Runtimes do not carry their own copies; the published agenthood npm package bundles the same `skills/` files, so any checked-out repo can run members.
2. **TypeScript runtime** — `npx agenthood run <member> "<task>" [--provider <name>]` driven by `.agenthood/config.json` (members list, provider priority, failover, quality gates). Used interactively and in CI.
3. **CI review gate** — a composite `agent-analysis` action + `decision-gate.sh` run a member (e.g. the-reviewer) over every pushed diff and post a `The Reviewer — Analysis` PR comment. The agent ends its report with `<!--AGENTHOOD_DECISION: blocking=true|false warnings=N-->`; the gate fails the workflow on blocking findings, conflicting verdict blocks (prompt-injection defense), trailing content, or too many warnings. Stale analysis comments are marked outdated.

**Provider and credential choices (verified during adoption):**

- LLM: OpenCode Go (`https://opencode.ai/zen/go/v1/chat/completions`, model `deepseek-v4-flash`). API keys are per-consumer: an `OPENCODE_API_KEY` valid for one project returns `401 Invalid API key` in another, so each repo/consumer needs its own Go subscription key from https://opencode.ai/auth.
- Transport: the gateway sits behind Cloudflare and rejects `urllib`'s TLS fingerprint (HTTP 1010); the update script calls it via `curl` and the runtime handles the same via its SDK stack. Future HTTP clients must replicate that behavior or they 1010-block.
- Fallbacks: `.agenthood/config.json` orders `opencode-go` first, then `groq` (`llama-3.3-70b-versatile` per AGENTS.md), with runtime failover across providers.
- Grounding (learned on fworks-tech): LLM-generated content must (a) state only facts present in the source events — never assert "zero commits"/"no changes" when the events API simply omitted commit details; (b) fetch missing push commits via the compare API so the model sees real work; (c) admit when data is absent instead of inventing it.

## Alternatives Considered

| Option | Pros | Cons | Why Rejected |
|--------|------|------|-------------|
| Groq-only default (AGENTS.md baseline) | Free tier, already documented | No runtime, no shared prompt source, weaker control of LLM output | Kept as the fallback provider, not the primary |
| Plain prompts pasted into each tool | Zero setup | Drifts per tool; impossible to keep in sync; no CI gate | Single source of truth is the whole point |
| Hand-written reviewer YAML + prompts per repo | No external dependency | Duplicates logic across repos; no failover or decision gate | Reuse agenthood's tested action + scripts instead |
| Anthropic-scripted agents everywhere | High quality | Provider lock-in; ignores opencode/Codex ecosystem; cost | The Envoy exists precisely to stay provider-neutral |

## Consequences

Becomes easier:

- One `SKILL.md` edit rewords a member everywhere; the Envoy/Sentinel keep skills consistent and drift-free across providers.
- Provider portability and failover are built into the runtime.
- PR reviews and generated README content share one grounded quality bar with an auditable decision gate.

Becomes harder / new risks:

- CI depends on the published `agenthood` npm package and on valid per-consumer `OPENCODE_API_KEY` secrets — a bad key silently degrades LLM features to fallbacks.
- Cloudflare protection means the TLS behavior of any new HTTP client matters (1010 blocks).
- Prompt injection via diffs is real; the decision gate's fail-closed rules (last-verdict-only, conflict rejection) are mandatory, not optional.
- OpenCode Go costs ($5 first month, then $10/month) plus usage limits; peak-hour pricing applies to `deepseek-v4-flash`.
